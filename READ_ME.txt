# NE-AFM Force Curve Classification

This repository contains the machine-learning and deep-learning notebooks, processed training data, trained model, and test files used for classification of nanoendoscopy atomic force microscopy (NE-AFM) force curves.

## 1. Important Note About the Training Data

The original `.jpk-qi-data` files used for model training are very large and are therefore **not included in this repository**.

In each model notebook, the **first cell contains the code used to read the original `.jpk-qi-data` files and convert them into the training dataset**.

Because the original `.jpk-qi-data` training files are not provided, users should **skip this first conversion cell**.

Instead, the already processed training dataset is provided as:

```text
X_force_curves.npy
```

After importing the required libraries, load the training data directly using:

```python
import numpy as np

X = np.load("X_force_curves.npy")

print(X.shape)
```

The expected shape is:

```text
(2048, 256)
```

This means that the dataset contains:

- 2048 force curves
- 256 data points per force curve

Therefore, when running any of the model notebooks, the recommended procedure is:

```text
1. Import the required libraries
2. Skip the first .jpk-qi-data conversion cell
3. Load X_force_curves.npy
4. Continue running the remaining cells of the notebook
```

For example:

```python
import numpy as np

X = np.load("X_force_curves.npy")
```

This `X` variable replaces the `X` generated by the first `.jpk-qi-data` conversion cell.

## 2. Machine-Learning and Deep-Learning Notebooks

All tested machine-learning and deep-learning models are provided as separate Jupyter Notebook files.

Examples include:

```text
xgb.ipynb

SVM.ipynb
```

Other tested model notebooks are also included in the repository.

Each notebook originally starts with a `.jpk-qi-data` conversion cell that generates the training dataset.

Since the original raw training files are not included, **do not run that first conversion cell**.

Instead, load:

```text
X_force_curves.npy
```

and then continue with the remaining cells for preprocessing, training, validation, and evaluation.

The workflow for each notebook is therefore:

```text
Open model notebook
        ↓
Import required libraries
        ↓
Skip first JPK conversion cell
        ↓
Load X_force_curves.npy
        ↓
Continue remaining notebook cells
```

## 3. Best Trained Model

The best-performing deep-learning model was a **1D ResNet**.

The trained model is provided as:

```text
resnet1d_traced.pt
```

The model is saved in PyTorch traced format and can be loaded without retraining.

Example:

```python
import torch

model = torch.jit.load("resnet1d_traced.pt")
model.eval()
```

This trained model is used by the supplied testing script to classify new `.jpk-qi-data` files.

---

## 4. Testing the Trained Model

The repository includes:

```text
test.py
```

for testing the trained 1D ResNet model on a new `.jpk-qi-data` file.

The command format is:

```bash
python test.py input.jpk-qi-data output.tsv
```

A sample test file is provided as:

```text
test1.jpk-qi-data
```

To test the supplied example file, run:

```bash
python test.py test1.jpk-qi-data test_output.tsv
```

The testing workflow is:

```text
test1.jpk-qi-data
        ↓
      test.py
        ↓
Force-curve extraction
and preprocessing
        ↓
resnet1d_traced.pt
        ↓
Force-curve classification
        ↓
   test_output.tsv
```

Make sure the following files are available in the working directory:

```text
test.py
test1.jpk-qi-data
resnet1d_traced.pt
```

## 5. Expected Test Output

A reference output file is also supplied:

```text
test.tsv
```

After running:

```bash
python test.py test1.jpk-qi-data test_output.tsv
```

the generated:

```text
test_output.tsv
```

should have the same general structure and classification results as the supplied:


The supplied `test.tsv` file can be used to verify that:

- the `.jpk-qi-data` file is read correctly,
- the force curves are extracted correctly,
- the preprocessing procedure is working correctly,
- the trained `resnet1d_traced.pt` model is loaded correctly, and
- the final classification pipeline is working as expected.

## 7. How to Run Any Model Notebook

For every model notebook, follow the same procedure.

### Step 1 — Open the Notebook

For example:

```text
xgb.ipynb
```

or:

```text
KNN.ipynb
SVM.ipynb
```

### Step 2 — Import the Required Libraries

Run the library-import statements required by the notebook.

For example:

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
```

Also import any additional libraries required by that specific model.

### Step 3 — Skip the First JPK Conversion Cell

The first cell reads the original large `.jpk-qi-data` training files and generates `X`.

Since those files are not provided, **do not execute this cell**.

### Step 4 — Load the Provided Training Dataset

Run:

```python
X = np.load("X_force_curves.npy")
```

You can verify the dataset using:

```python
print(X.shape)
```

Expected result:

```text
(2048, 256)
```

### Step 5 — Continue With the Remaining Cells

Once `X` has been loaded, continue running the notebook from the next preprocessing/model-training section.

No other change to the model notebook should normally be required.

## 9. Raw Data and Reproducibility

The raw `.jpk-qi-data` training files were not uploaded because of their large size.

The original JPK conversion code has been retained in the first cell of each model notebook so that the complete data-preparation procedure remains documented.

However, for normal use of this repository, users should skip that conversion cell and directly load:

```text
X_force_curves.npy
```

This provides the same processed training input used by the model notebooks while avoiding the need to store or repeatedly process the large raw JPK files.
